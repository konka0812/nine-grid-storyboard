# Reference Contract

每张参考图都要说明它能控制什么，不能控制什么。不要写“全参考”“按这张图”“保持一致”这类没有边界的说法。

## 槽位语法

```markdown
REF-01 · 顺序 1 · `input/product.png`《产品正面图》
- 用途：主体身份
- 控制：轮廓、长宽比、主体材质、主色、可见按钮/接口数量
- 不得控制：背景、镜头运动、尚未发生的功能动作
- 观察状态：已确认 / 推测 / 未验证
```

同一张图承担两个作用时拆成两个槽位。例如一张角色定妆图同时锁定脸型和本场服装，就分别写“角色身份”和“造型状态”，并在两个槽位里写清各自边界。

## 用途词表

| 用途 | 可以控制 | 默认不能控制 |
| --- | --- | --- |
| 主体身份 | 产品轮廓、比例、材质、部件数量；角色脸型、体型、发型、识别标记 | 动作、镜头、背景、尚未出现的道具、**首帧构图** |
| 造型状态 | 本场服装、湿污、破损、亮屏、开合状态 | 新人物、新地点、新功能 |
| 场景地理 | 入口、出口、区域关系、固定锚点、光源方向 | 人物情绪、剧情结果 |
| 构图 | 占画比例、主体位置、留白、镜头一侧 | 主体身份和数量 |
| 尺度 | 主体与环境或配件的相对大小 | 风格、身份、动作结果 |
| 风格 | 色彩层级、光比、笔触、景深、材质渲染方式 | 剧情事实、主体结构 |
| 分镜计划 | 九格顺序、景别变化、信息点、节奏 | 分镜边框、编号、纸纹、主体身份 |
| 状态锚点 | 上一段结尾的位置、持物、朝向、光线 | 本段完整镜头设计 |

## 输入组合

### 有原图 / 角色图 / 场景图

推荐：

```text
IMAGE 1：主体身份
IMAGE 2：3×3 分镜关键帧图
```

原因：原图锁产品或角色身份，九宫格锁镜头节奏。生成视频时，主体必须始终匹配原图，而不是匹配九宫格里的风格化复制。

首帧警告：视频模型在没有显式约束时，会把 IMAGE 1 的构图当成视频开头。所以双图提交的视频提示词必须包含首帧锚定块（见 [video-prompt-templates.md](video-prompt-templates.md)）：**视频第一帧对应九宫格第一格，不是 IMAGE 1**。九宫格第一格就是本片段的开场镜头；IMAGE 1 里呈现的姿势、机位和背景只是身份快照，不是开场状态。

### 只有九宫格

九宫格同时承担主体身份和分镜计划。视频提示词必须写清：

1. 主体轮廓和比例。
2. 材质或服装。
3. 关键部件和数量。
4. 场景锚点。
5. 光线和调色板。
6. 开头与结尾状态。

### 没有任何图片

先输出九宫格图提示词，不直接输出最终视频提示词。若用户明确选择文生视频，则视频正文必须包含完整的静态视觉锚点；不能只写“保持已有外观”。

## 观察边界

只有以下两种情况可以声称参考图内容已被核对：

1. 运行环境获授权查看过图片。
2. 用户或权利人提供了可核对的文字说明。

否则写“未验证”。不要声称水印、文字、裁切、按钮数量已经通过检查。

## 禁止项

1. 不把文件名、版本号、`REF` 槽位或内部规则写进可复制生成提示词。
2. 不把所有参考都塞给每一格；只绑定本格真正需要的身份、地理、构图或状态。
3. 不用风格参考改写主体结构。
4. 不用构图参考带入图中没有的人物、文字或道具。
5. 不用上一段尾帧发明新终点；它只锚定已经确认的 Carry-in。
